🏛️ 1. 프로젝트 개요 및 구조 아키텍처

Study Cafe Tycoon은 수험생과 개발자를 위한 감성 힐링 2.5D 이소메트릭 스터디 카페 경영 시뮬레이션 게임입니다. 고도 4(Godot 4) 엔진을 기반으로 구축되었으며, 70개 이상의 독립 비즈니스 서브시스템과 120개의 무결성 자동 검증 테스트 스위트를 탑재한 엔터프라이즈급 타이쿤 게임 아키텍처를 자랑합니다.

💡 2. 해당 아키텍처를 채택한 핵심 이유 (ADR)

1) 2.5D 절차적 벡터 렌더링 Engine (`_draw()` Fallback) 채택

모바일 게임 및 익스포트 파이프라인에서 PNG 리소스 파일 손상(File Corruption)이나 `.import` 누락 문제 발생 시, 비어있는 검은 화면이나 에러 크래시가 발생하는 위험을 방지하기 위해 100% Procedural Vector Fallback Rendering 기법을 채택했습니다.

  • 외부 PNG 자원이 부재하더라도 cafe_view.gd의 _draw() 함수가 원목 패턴, 아크릴 파티션, LED 스탠드, 노트북, 의자 및 고객 그래픽을 절차적 도형과 그라데이션 알고리즘으로 직접 렌더링합니다.
  • 어떠한 자원 누락 환경에서도 0초 무중단으로 게임 화면이 안전하게 표시되는 극강의 견고함(Robustness)을 제공합니다.

2) 단일 반응형 상태 오토로드 (`GameState.gd`) 및 Signal-Up / Call-Down

70개에 달하는 타이쿤 서브시스템(커피 로스팅, 스마트 사물함, 무중력 수면 캡슐, ANC 헤드폰 대여 등) 간의 결합도(Coupling)를 낮추고 데이터 일관성을 유지하기 위해 중앙 집중식 GameState 오토로드를 구축했습니다.

  • UI 패널은 오토로드로 직접 상태 변경을 요청(Call-Down)하고, 오토로드는 커스텀 Signal(Signal-Up)을 방출하여 뷰와 오디오가 반응형(Reactive)으로 동기화됩니다.

3) 스마트폰 가로 해상도 비율 동적 스케일링 (`canvas_items` + `expand`)

다양한 종횡비(16:9, 19.5:9, 20:9)를 가진 현대 스마트폰(iPhone 13~16, 갤럭시 등) 화면에서 찌그러짐이나 레터박스(Letterbox) 없이 가로형 풀스크린으로 확장할 수 있도록 project.godot 설정을 stretch/mode="canvas_items", stretch/aspect="expand"로 고정했습니다.

🔥 3. 개발 중 직면했던 주요 난제 및 기술적 해결 방안

✔ 해결 완료 [난제 1] 뷰 포트 스크롤 시 공간-오브젝트 이탈 (Scroll Disconnect Issue)

[문제 원인] 마우스 드래그 및 스크롤 시 바닥 렌더링에는 view_offset.y가 적용되었으나, 메인 집중 방, 라운지, 커피 바, 사물함, 책상 좌표 연산에는 view_offset이 유기적으로 합산되지 않아 스크롤 시 공간과 책상/손님 캐릭터가 서로 따로 노는 이탈 현상이 발생함.

[해결 책] cafe_view.gd 내 draw_integrated_multi_room_layout() 및 고객 렌더링 연산 전체에 var vo = view_offset 좌표 오프셋을 1:1 통합 적용하고, 드래그 경계(clamp)를 설정하여 스크롤 시 **모든 오브젝트가 하나의 통합 2.5D 공간으로 매끄럽게 동기화**되도록 수선했습니다.

✔ 해결 완료 [난제 2] GDScript Node Object.get() 2인자 파싱 에러 (Parse Error Bug)

[문제 원인] GDScript의 Dictionary .get(key, default) 형태와 달리, Autoload Node 객체의 Object.get(property) 함수는 엄격히 **1개의 인자**만 허용하므로 2개의 인자를 전달 시 fatal 파싱 에러가 발생함.

[해결 책] `GameState.get("property")` 형태의 2인자 구문을 모두 제거하고, 딕셔너리 안전 접근자인 `GameState.upgrades.get("category", default)` 구조로 전환하여 파싱 에러를 근본적으로 차단했습니다.

✔ 해결 완료 [난제 3] 모바일 해상도 오버레이 팝업 우측 잘림 (UI Cropping Issue)

[문제 원인] 하단 메뉴(가구 상점, 로스팅 바, 베이커리, 캐스팅 등) 팝업 패널 크기가 고정 750px로 넓게 설정되어 해상도가 낮은 모바일 기기 화면에서 오른쪽 영역이 잘려나가는 현상 발생.

[해결 책] 모든 오버레이 팝업 패널의 custom_minimum_size를 **`Vector2(660, 460)`**으로 규격화하고 PRESET_CENTER 정렬을 적용하여 모바일 화면에서도 중앙에 완벽히 피트되도록 보정했습니다.

✔ 해결 완료 [난제 4] iOS PCK 패키징 시 이미지 자원 런타임 누락 (Resource Loader Export Issue)

[문제 원인] 익스포트된 PCK 환경에서 `Image.load_from_file()`을 직접 호출할 경우 `.import` 자원 트래킹이 유실되어 익스포트 리소스 경고 및 파일 로딩 실패가 발생함.

[해결 책] `ResourceLoader.load()`를 1순위로 시도하고 실패 시 `Image.load_from_file()`을 2순위 폴백으로 실행하는 하이브리드 로더 load_tex_safe()를 구축했습니다.
