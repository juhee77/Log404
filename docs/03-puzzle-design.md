# 퍼즐 설계 가이드

## 문서 메타
- 목적: 퍼즐 생성/검수 기준을 표준화해 난이도와 품질을 일정하게 유지한다.
- 독자: 콘텐츠 기획자, 내러티브 디자이너, QA.
- 입력: 로그/문서 데이터 유형, 챕터 목표, 단서 구조.
- 출력: 퍼즐 템플릿, 난이도 규칙, 검수 체크리스트.

## 설계 원칙
- 기술적으로 보여도 해석은 직관적이어야 한다.
- 퍼즐당 핵심 관찰 포인트는 1~2개로 제한한다.
- 추론 결과는 다음 해금 행동과 직접 연결되어야 한다.
- 실제 코딩 지식 없이도 풀 수 있어야 한다.

## 퍼즐 표준 템플릿
- 전제: 어떤 의심 상황을 다루는가
- 단서 출처: 로그/메일/채팅/출입기록 중 무엇을 쓰는가
- 플레이어 관찰: 무엇이 어긋나 보이는가
- 추론: 플레이어가 내려야 하는 결론
- 보상: 해금되는 문서/권한/보드 카드

## 정규화된 퍼즐 예시
- 로그인 시간 불일치: 인증 로그 vs 출입 기록 비교로 대리 접속 의심
- 정상 에러 위장: 반복 오류 코드가 암호문 패턴 역할
- 삭제 레코드 복구: 누락된 프로젝트명으로 사건 동기 노출
- 타임존 함정: 시스템 간 시간 기준 차이로 알리바이 붕괴
- 대화 순서 왜곡: 메신저와 배포 로그의 순서 충돌 확인

## 난이도 상승 규칙
- 초반: 단일 데이터 소스 비교
- 중반: 2개 소스 교차 검증
- 후반: 시간축 + 행위자 + 문맥 동시 추론

## 검수 체크리스트
- 추론에 필요한 정보가 모두 노출되는가
- 오해를 유발하는 불필요 노이즈가 과도하지 않은가
- 정답 근거를 문서 2개 이상에서 확인 가능한가
