# LOG:404 스토리 강화안

## 목적
- 현재 MVP 3챕터 서사를 더 강하게 만들기 위한 구체 작업안을 고정한다.
- 시즌형 5챕터 확장을 할 경우 이어서 사용할 챕터 4-5 방향을 정의한다.
- 기존 서사의 강점은 유지하고, `앨리스가 너무 빨리 읽히는 문제`, `존스 미끼 밀도 부족`, `존의 능동성 부족`을 보강한다.

## 전제
- 현재 단일 기준 문서상 MVP 범위는 `사건 1개 / 챕터 3개 / 엔딩 2개`다.
- 따라서 본 문서는 두 트랙으로 나눈다.
  - 트랙 A: MVP 3챕터 유지, 서사 밀도 강화
  - 트랙 B: 시즌형 5챕터 확장

## 트랙 A: MVP 3챕터 유지 강화

### 목표
1. 플레이어가 존스를 더 강하게 의심하게 만든다.
2. 앨리스를 너무 빨리 확신하지 못하게 한다.
3. 존을 단순 피해자가 아니라 마지막까지 움직인 인물로 보이게 만든다.
4. 챕터 3 직후 보고서 제출 전 감정 피크를 만든다.

### 추가 문서 1
- 역할: 존스를 더 그럴듯한 용의자로 보이게 만드는 표면 증거
- 권장 해금 시점: 챕터 2
- 권장 source_type: `incident_note`

```json
{
  "id": "note_security_jones_override",
  "source_type": "incident_note",
  "title": "보안 인계 메모 / Jones 수동 개방 요청",
  "chapter": 2,
  "content": "2026-04-16 23:15:12 KST | author=sec.shift_b\nsubject=svc-corridor-3 수동 개방 요청\n\n- 요청자: jones.m\n- 사유: '존이 지금 서버 쪽에 다시 붙었을 수 있다. 문 열어.'\n- 특이사항: 요청자는 매우 격앙돼 있었고, 절차 생략을 요구함.\n- 후속 메모: 현장 충돌 가능성 우려로 일단 보류.\n\n덧붙임:\n요청 문맥만 보면 존스를 추적 또는 압박하려는 움직임처럼 보인다."
}
```

- 의도:
  - 첫 읽기: 존스를 폭력적이고 위험한 인물처럼 보이게 만든다.
  - 재해석: 실제로는 사후 수습 또는 긴급 차단 시도였을 수 있다.

### 추가 문서 2
- 역할: 앨리스의 즉시 유죄감을 늦추는 완충 증거
- 권장 해금 시점: 챕터 3
- 권장 source_type: `mail_draft`

```json
{
  "id": "mail_alice_unsent_escalation",
  "source_type": "mail_draft",
  "title": "미전송 메일 / Alice 내부 보고 초안",
  "chapter": 3,
  "content": "From: alice.h@log404.local\nTo: exec-response@log404.local\nSubject: John 관련 야간 접근 대응 초안\n\n존 계정의 재접속 흔적을 확인했습니다.\n다만 현 시점에서 전체 로그를 그대로 올리면 관련자 실명과 미검증 정황이 함께 확산될 수 있습니다.\n먼저 당사자 안전과 사실관계부터 확인할 시간을 요청합니다.\n\n보내지 않은 메모:\n- 지금 올리면 존이 완전히 끝난다.\n- 누군가를 보호하려는 건지, 미루려는 건지 모르겠다."
}
```

- 의도:
  - 첫 읽기: 앨리스가 뭔가 숨긴 것은 맞지만, 출발점이 냉혈한의 악의만은 아니라는 인상을 준다.
  - 재해석: 보호 욕망이 통제로 넘어가는 경계선에 있던 사람으로 보이게 만든다.

### 추가 문서 3
- 역할: 존의 능동성과 마지막 의지를 보여주는 기록
- 권장 해금 시점: 챕터 2
- 권장 source_type: `private_note`

```json
{
  "id": "note_john_contingency_map",
  "source_type": "private_note",
  "title": "로컬 메모 / contingency_map.txt",
  "chapter": 2,
  "content": "1. bastion 경로 다시 열리면 바로 스냅샷 남길 것\n2. Jones가 또 소리치더라도 그 사람이 먼저 선 넘지는 않을 거다\n3. Alice는 끝까지 맥락을 보려 할 거다. 다만 너무 늦지 않으면 좋겠다\n4. 이게 진짜면 누군가는 이미 알고 있고, 누군가는 덮으려 한다\n5. 내가 사라지면 '퇴사'로 정리될 가능성이 크다\n\n마지막 줄:\n적어도 누군가는 전체 순서를 다시 읽게 만들어야 한다."
}
```

- 의도:
  - 존이 단순히 당한 사람이 아니라 마지막까지 정리와 폭로를 시도한 인물로 읽힌다.
  - 앨리스와 존스를 둘 다 단선적으로 못 보게 만든다.

### 보고서 직전 감정 피크
- 구현 대상: 챕터 3 종료 직후 브리핑/활동 로그/보고서 가이드
- 목표 문장:
  - "누가 범인인가"보다 "나는 누구의 설명을 빌려 여기까지 왔는가"를 먼저 떠올리게 만든다.
- 권장 UI 노출:
  - `activityLog`에 자가 의심 한 줄 추가
  - `reportGuide`에 재독 권장 문서 3개 노출
  - `storyRoadmap` 대신 `재검토 포인트` 카드 노출

예시 문구:
- `지금 필요한 건 새 증거가 아니라, 이미 읽은 기록을 누구의 말 없이 다시 읽는 일일지도 모릅니다.`
- `추천 재검토: chat_alice_late_help, note_if_i_disappear, log_alice_dm_read`

### MVP 기준 실제 작업 순서
1. `data/documents.json`에 신규 문서 3개 추가
2. `data/chapter_gates.json`에 해금 타이밍 연결
3. `data/clues.json` 일부 요구 문서 조정 또는 선택 퍼즐 보강
4. 웹/엔진 브리핑 문구에 보고서 직전 감정 피크 추가
5. 테스트에 신규 문서 해금과 보고서 전 재검토 가이드 반영

## 트랙 B: 시즌형 5챕터 확장

### 주의
- 이 트랙은 MVP 범위를 넘어선다.
- 실제 구현 전 `docs/08-mvp-scope.md` 수정이 선행되어야 한다.

## 챕터 4 제안
- 제목: `사라진 사람은 누구를 믿었나`
- 감정: 혼란, 부정, 죄책감
- 서사 목표:
  - 존이 마지막까지 믿은 사람은 앨리스였다는 사실을 드러낸다.
  - 반전을 단순 범인 공개가 아니라 친밀함의 붕괴로 바꾼다.

### 챕터 4 핵심 문서 후보
1. `voice_john_last_for_alice_transcript`
2. `chat_john_alice_archive_fragment`
3. `alice_archive_rule_override`
4. `john_safe_release_checklist`

### 챕터 4 퍼즐 질문
- 존은 왜 마지막까지 앨리스를 믿었는가
- 앨리스는 왜 읽고도 답하지 않았는가
- 보호와 방치의 경계는 어디서 무너졌는가

## 챕터 5 제안
- 제목: `네가 틀린 게 아니라, 네가 믿은 거야`
- 감정: 배신감, 연민, 자기혐오, 갈등
- 서사 목표:
  - 앨리스가 로그를 조작한 것은 사실이지만, 그 이유가 존을 지키려는 왜곡된 보호였음을 보여준다.
  - 플레이어가 정의와 인간성 사이에서 갈등하게 만든다.

### 챕터 5 핵심 문서 후보
1. `alice_confession_fragment`
2. `cache_patch_rationale_internal`
3. `policy_coverup_thread`
4. `john_final_release_packet`

### 챕터 5 퍼즐 질문
- 앨리스는 무엇을 숨겼고 무엇은 지키려 했는가
- 회사의 공식 서사는 누구를 위해 설계됐는가
- 플레이어는 어떤 보고서를 남길 것인가

## 권장 의사결정
- 바로 구현할 다음 작업은 트랙 A를 우선한다.
- 트랙 A는 현재 배포된 웹 데모와 바로 연결되고, 트랙 B로 확장해도 폐기되지 않는다.
- 트랙 B는 MVP 검증 후 정식 시즌형 구조로 넘어갈 때 착수한다.
