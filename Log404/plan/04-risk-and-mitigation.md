# 리스크와 대응 전략

## 문서 메타
- 목적: 일정/품질/플랫폼 리스크를 사전에 식별하고 대응책을 고정한다.
- 독자: 프로젝트 오너, 개발자, QA.
- 입력: 로드맵, MVP 범위, 플랫폼 요구사항.
- 출력: 리스크 목록, 조기 신호, 대응 플랜.

## 주요 리스크
- 일정 지연: 콘텐츠량 과다 또는 기능 확장 욕심
- 콘텐츠 과다: 챕터/퍼즐 수가 MVP 한계를 초과
- UI 복잡도: 정보 밀도 증가로 가독성 악화
- 플랫폼 이슈: macOS 빌드/서명/notarization 지연

## 조기 신호
- 주간 목표 2회 연속 미달
- 플레이테스트에서 동일 막힘 반복 발생
- 플랫폼별 빌드 실패가 48시간 이상 미해결

## 대응책
- 범위 축소 우선순위표를 사전 확정(시각 효과 > 부가 기능 > 콘텐츠 확장)
- 챕터당 핵심 퍼즐 수 상한 설정
- UI 변경은 가독성 기준(대비/검색 성공률)으로만 승인
- macOS 검증을 4단계 직전이 아니라 2단계 말부터 주기 수행

## 에스컬레이션 기준
- 진행 불가 버그 1건 이상 24시간 지속 시 즉시 스프린트 재계획
- 저장 손상 재현 시 신규 기능 개발 중단 후 안정화 우선
